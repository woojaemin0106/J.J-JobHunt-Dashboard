# Interview Demo Runbook (5분)

- 문서 ID: `DR-5MIN`
- 문서 버전: `v2026.03.27`
- 기준일: `2026-03-27`
- 목적: 면접관 앞에서 동일 품질의 데모를 재현하기 위한 운영 절차 고정

## 1. 데모 시작 전 체크(1분)

1. 앱 실행
- `npm install`
- `npm run dev`
- `http://localhost:5173` 접속

2. 환경 확인
- Supabase 사용 가능 시: 데모 로그인 버튼 노출 확인
- Supabase 이슈 시: 게스트 로그인 버튼으로 대체 가능 확인

3. 콘솔 확인
- 치명 오류 없음 확인

## 2. 표준 시연 동선(총 5분)

1. 00:00~00:40 로그인 화면
- `게스트로 바로 입장` 또는 `데모로 바로 보기` 클릭
- "원클릭 진입" 구조를 먼저 설명

2. 00:40~02:10 지원 현황(`/applications`)
- 검색/상태 필터를 1회 시연
- 칸반 카드 상태 전환 또는 추가/수정 1회 시연

3. 02:10~03:10 이력서 버전(`/resume`)
- 특정 공고 선택
- 버전 추가 또는 삭제 1회 시연

4. 03:10~04:10 메모(`/notes`)
- 메모 추가 후 바로 수정 또는 삭제 시연

5. 04:10~05:00 통계(`/statistics`)
- 상태 분포/월별 추이 확인
- "데이터 입력이 통계에 반영되는 구조" 설명

## 3. 홈 퀵플로우 사용법

데모 로그인 후 홈 화면에서 `Interview demo quick flow` 패널을 사용합니다.

- `지원 현황 보드 보기`
- `메모 화면 확인`
- `통계 화면 확인`

면접 중에는 해당 버튼으로 화면 전환해 동선 이탈을 최소화합니다.

## 4. 장애 대응 플랜

1. 인증 장애(예: Supabase 네트워크 실패)
- 즉시 `게스트로 바로 입장`으로 전환
- "외부 의존성 장애 대비 경로"임을 설명

2. 데이터가 비어 있는 경우
- Empty state CTA로 데이터 생성 시연 전환
- 지원서/메모/버전 추가 후 통계 반영까지 연결

3. 성능 저하/일시 멈춤
- 페이지 리로드 1회
- 동일 동선 재개

## 5. 면접관 질문 유도 포인트

- 왜 테스트를 unit/integration/e2e로 나눴는지
- 왜 인증/데이터 경계를 먼저 안정화했는지
- 왜 데모 경로를 "원클릭 + 퀵플로우"로 설계했는지

## 6. 데모 성공 기준

- 5분 내 핵심 화면 4개 이상 시연 완료
- 인증 실패 없이 진입 성공(실패 시에도 게스트 경로로 복구 성공)
- 검색/필터 또는 CRUD 조작 최소 1회 + 통계 반영 설명 완료
